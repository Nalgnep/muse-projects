Hands-on · 八步实操

照着做：从开服务器到 AI 日报

每步都有可复制的命令/代码和完成标志。没看到完成标志，不要往下走——IoT 排障最耗时的就是带着上一步的错搭下一步。

1

开一台 VPS（阿里云 ECS）并装好 Docker

控制台选 Ubuntu 22.04、2核4G，按量或包月均可。调试期安全组临时放行 22（SSH）、8080（ThingsBoard）和 1883（MQTT）。上线后只留 22 和 443：8080 收到本机，MQTT 改走 8883 加 TLS，设备 Token 不进代码仓库，也不要写进前端页面。

终端 · SSH 登录后执行
sudo apt update && sudo apt install -y docker.io docker-compose-plugin
sudo systemctl enable --now docker
sudo docker run --rm hello-world   # 看到 Hello from Docker 才算装好
  • 完成标志：hello-world 正常输出
  • 云防火墙与系统防火墙规则一致，没有多开端口
2

用 Docker Compose 拉起 ThingsBoard

单机学习版用官方镜像 + 内置 PostgreSQL 即可。数据目录挂到宿主机，重启不丢数据。

docker-compose.yml
services:
  thingsboard:
    image: thingsboard/tb-postgres:latest
    ports:
      - "8080:9090"
      - "1883:1883"
    volumes:
      - ./tb-data:/data
      - ./tb-logs:/var/log/thingsboard
    restart: unless-stopped
启动
mkdir -p tb-data tb-logs && sudo chown -R 799:799 tb-data tb-logs
docker compose up -d
# 浏览器打开 http://你的服务器IP:8080
# 系统管理员：sysadmin@thingsboard.org / sysadmin（登录后立刻改密码）
  • 完成标志：能打开登录页并进入租户后台
3

建设备与遥测字段：先定“字典”，再谈数据

在 ThingsBoard 里建 1 个设备档案（Device Profile）+ 6 台设备，每台会拿到一个 Access Token。全车间统一遥测键名，后面规则和 AI 都靠它：

temperature  温度 ℃      vibration  振动 mm/s
pressure     压力 MPa    power      功率 kW
humidity     湿度 %RH    rpm        转速 r/min
status       状态码：0 停机 / 1 运行 / 2 待机
  • 完成标志：6 台设备各有独立 Token，键名表贴在工位上（真的，贴纸质版最有效）
4

模拟数据接入：用 Python 当“假传感器”

没有硬件也能练全链路。这个脚本就是本页上方仿真的真实版：正弦趋势 + 随机噪声 + 偶发异常，每 2 秒发一包 MQTT。

simulator.py · pip install paho-mqtt
import json, math, random, time
import paho.mqtt.client as mqtt

HOST, TOKEN = "你的服务器IP", "设备AccessToken"
client = mqtt.Client()
client.username_pw_set(TOKEN)          # ThingsBoard 用 Token 作用户名
client.connect(HOST, 1883, 60)

t = 0
while True:
    t += 1
    temp = 62 + 10 * math.sin(t / 18) + random.uniform(-1.5, 1.5)
    if random.random() < 0.04:        # 4% 概率模拟一次异常升温
        temp += random.uniform(22, 30)
    payload = {
        "temperature": round(temp, 1),
        "vibration": round(2.1 + random.uniform(-0.5, 0.7), 2),
        "power": round(38 + random.uniform(-4, 5), 1),
        "status": 1,
    }
    client.publish("v1/devices/me/telemetry", json.dumps(payload))
    print("sent:", payload)
    time.sleep(2)
  • 完成标志：设备详情页 Latest telemetry 实时跳动
  • 断开脚本 30 秒，看板能看出“掉线”——这一步验证的是心跳，不是数据
5

搭看板：四类组件就够，别堆满屏

新建 Dashboard，按这个顺序放组件，班组长 3 秒内能找到答案：

  • 状态区：设备卡片（名称 + 在线状态 + 当前温度），红/黄/绿只表示状态，不做装饰
  • 趋势区：温度、振动时序曲线，默认看最近 1 小时，带阈值线
  • 告警区：Alarm 表格（时间、设备、级别、确认按钮）
  • 摘要区：放一个文本卡片，URL 指向第 7 步 VPS 服务返回的 AI 摘要
排版原则：一块屏只回答一个问题——“现在有没有事？”趋势和明细点进去再看。大屏上塞 20 个图表，结果是谁都不看。
6

规则链告警：阈值 + 持续时间，缺一不可

在规则链里串：Message Type Switch → Telemetry 过滤 → Script 节点判阈值 → Create Alarm → 通知节点（邮件 / Webhook 到钉钉、企微）。核心判断逻辑长这样：

规则链 Script 节点（JavaScript）
// 只看温度遥测，超过 85℃ 才往下走
if (msgType !== 'POST_TELEMETRY_REQUEST') return { msg: msg, metadata: metadata, msgType: msgType };
var temp = msg.temperature;
if (temp === undefined) return { msg: msg, metadata: metadata, msgType: 'IGNORE' };
metadata.alarmText = '温度 ' + temp + '℃，超过阈值 85℃';
return { msg: msg, metadata: metadata, msgType: temp > 85 ? 'ALARM' : 'OK' };
  • 关键设置：告警要加「持续 30 秒才触发」+「恢复后自动清除」，否则传感器抖一下就刷屏
  • 完成标志：跑第 4 步脚本造一次异常，告警表出现记录，手机收到通知
7

接 DeepSeek：在 VPS 上加一个 AI 摘要小服务

思路：服务每小时从 ThingsBoard REST API 拉聚合值（均值/峰值/告警数），拼成提示词调 DeepSeek，把结果存下来给看板文本卡片读。喂聚合，不喂流水——省钱、更快、摘要质量反而更高。

ai_summary.py · 核心片段
import os, requests

DEEPSEEK_KEY = os.environ["DEEPSEEK_API_KEY"]  # 只放环境变量

def make_summary(stats: dict) -> str:
    prompt = f"""你是车间设备助理。根据最近1小时数据写一段80字以内的中文摘要，
包含：整体状态、最值得关注的一台设备、一条明确建议。数据：
平均温度 {stats['avg_temp']}℃，峰值 {stats['max_temp']}℃（{stats['max_device']}），
平均振动 {stats['avg_vib']} mm/s，告警 {stats['alarms']} 次，总功率 {stats['power']} kW。
不要编造数据里没有的数字。"""
    r = requests.post(
        "https://api.deepseek.com/chat/completions",
        headers={"Authorization": f"Bearer {DEEPSEEK_KEY}"},
        json={"model": "deepseek-chat",
              "messages": [{"role": "user", "content": prompt}],
              "temperature": 0.3},
        timeout=30)
    return r.json()["choices"][0]["message"]["content"]
定时执行（crontab）
0 * * * * cd /opt/iot-ai && DEEPSEEK_API_KEY=你的Key /usr/bin/python3 ai_summary.py >> summary.log 2>&1
  • 完成标志：看板摘要区每小时自动换一段新文字，且数字和曲线对得上
  • 温度参数 0.2–0.4：摘要要稳，不要文采

上线：域名、HTTPS、备份，三件套别省

  • 反向代理：Nginx 把 8080 藏到 443 后面，Certbot 申请 Let's Encrypt 免费证书
  • 账号：关掉默认管理员，给班组长开只读看板账号，操作账号单独建
  • 备份：每天打包 tb-data 目录 + docker-compose.yml，存到阿里云 OSS 一份
  • 数据保留：遥测原始数据留 90 天，聚合数据长期留，别让磁盘被时序数据吃满
Nginx 反代片段
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;      # ThingsBoard 实时刷新走 WebSocket
    proxy_set_header Connection "upgrade";
}

Lab 03 · 规则告警实验

配一条你自己的告警规则

选指标、定阈值、选级别，保存后规则立刻对上方实时仿真生效。试试把温度阈值调到 60℃——你会马上明白为什么真实产线要加“持续时间”和“恢复回差”。

当前生效规则：温度 > 85℃（警告）· 振动 > 4.5 mm/s（严重）

好规则的三要素：阈值（多少算异常）+ 持续时间（抖动不算）+ 通知对象（谁必须处理）。只有阈值的规则，上线一周就会被班组静音。

Lab 04 · AI 摘要实验

DeepSeek 摘要的提示词，拆开给你看

AI 摘要质量差，通常不是模型问题，是喂的数据和提示词问题。记住这个结构：角色 + 数据 + 输出约束 + 禁止编造。回到上方看板点「生成 AI 摘要」，生成逻辑就是按这份模板、用实时聚合值在本页现场拼出来的（本页为课堂仿真，不会真的调用你的 API Key）。

喂什么数据

  • 最近 1 小时：各指标均值、峰值及峰值设备
  • 同期告警次数与未确认告警
  • 与上一时段的环比变化（涨/跌多少）
  • 不喂：秒级原始流水、设备 Token、任何密钥

摘要分工

  • 整点摘要：给班组长，80 字内，只讲异常和建议
  • 日报：下班前生成，含能耗、停机、告警 Top 3
  • 异常归因：告警触发时单独调一次，结合前后 10 分钟数据给排查方向——只给方向，不下结论

Troubleshooting · 排障手册

最常见的 5 个“没数据”，按这个顺序查

现象先查常见真因
设备一直离线服务器 1883 端口、安全组、Token 是否填错Token 复制时带了空格；安全组只开了 8080
有连接但看板没数遥测键名与看板组件绑定的键是否一致键名大小写不一致，如 Temp 与 temperature
告警不触发规则链是否设为当前 Root 链、告警持续时间设置改完规则链忘了保存，或阈值单位看错
